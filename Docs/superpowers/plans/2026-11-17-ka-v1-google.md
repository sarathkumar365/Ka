# Ka v1: Google Drive Inbox and Sheet Copy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner drops a statement PDF into a Drive folder from any device. Ka finds it, queues an import card in Pending, and imports it on approval. Every approved import and recategorisation is copied to a Google Sheet the owner can view.

**Architecture:**
- The spec's fallback applies. Google's Workspace MCP servers are not available to this account (the Developer Preview rejects Gmail accounts), so Ka uses the direct Google Drive API v3 and Google Sheets API v4 through the official Python client libraries.
- Both sit behind `DriveClient` and `SheetsClient` Protocols. A later MCP implementation can replace them without changing callers.
- Auth is the installed-app OAuth flow with a stored refresh token.
- The local CSV stays the store of truth, so a Google outage only delays the copy.

**Tech Stack:** `google-api-python-client`, `google-auth`, `google-auth-oauthlib`, FastAPI, APScheduler (from plan 1), React and TanStack Query.

**Spec:** `context/decisions.md`:
- the Google line
- the fallback line ("fall back to the direct Drive and Sheets APIs behind the same integration interface")
- the "Google via direct APIs" addendum (2026-11-17)

The owner's call on 2026-11-17: Drive inbox plus Sheet copy, with CSV as the store of truth.

**Owner setup (done):** Cloud project shared with the owner's Gmail MCP server, with the Drive and Sheets APIs enabled. The consent screen is in production and unverified, so the owner sees a one-time warning. The desktop OAuth client is "Ka desktop". There is a Ka folder, a statements folder and a finance sheet. Their IDs and the client file path go in the local `config.yaml` only.

## Global Constraints

- Requested scopes: `https://www.googleapis.com/auth/drive.readonly`, `https://www.googleapis.com/auth/spreadsheets`, `openid`, `https://www.googleapis.com/auth/userinfo.email`. Ka never writes to Drive, so it does not request `drive.file` even though the consent screen allows it.
- The consent screen is shared with another app. Ka never changes Cloud project settings.
- Secrets stay outside the code repo:
  - `google.client_file` is a path in the local `config.yaml`, used as is, never copied.
  - The token goes in `<data_repo>/local/google/token.json`, file mode 0600, git-ignored.
  - The client secret, token, account email, project ID and folder or sheet IDs never appear in code, tests, logs, activity text or docs.
- Local config keys: `google: {client_file, drive_folder_id, sheet_id}`. These are added to `config.yaml` in T1, together with the `Config` model change, so the running server's strict config never sees an unknown key.
- Library calls are taken from the current official docs (Drive v3 `files().list` and `files().get_media` with `MediaIoBaseDownload`; Sheets v4 `spreadsheets().get`, `batchUpdate` with `addSheet`, `values().clear` and `values().update`), never guessed. The builder ledgers the doc version checked.
- Stop condition: if Google rejects requests because the client has the "AI-powered agent" flag, stop and tell the owner, who will create a second client without the flag. Do not work around it.
- Import still needs the owner's approval. A downloaded PDF never goes into the finance store without it.
- Downloaded PDFs land in `cfg.statements_dir`. Drive file IDs already handled are stored in `app_state` key `drive_seen`, as a JSON list.
- Flag `google`, default off.
- Commits: commit guard; touch `.claude/.reviewed` only after a yes; no trailers; noreply author.

## Review Focus

1. The same PDF is in both Drive and the local folder, or is uploaded twice under different names. There is one import only: `already_imported` blocks the second, and the card says so (T3 test).
2. A non-statement file sits in the Drive folder. It is skipped with a reason in Settings, once (T3 test).
3. The refresh token is revoked or expired. The status says "reconnect Google" and nothing crashes (T1 test).
4. The sheet is deleted or a tab is renamed. The copy fails with a status line, the CSV is untouched, and the next copy recreates the tabs (T4 test).
5. A Drive sync runs while an import is being approved. They do not interleave, because both take `app.state.lock` (T3 test, two threads).

### Task 1: Google OAuth

**Files:**
- Create: `server/integrations/google/__init__.py`, `server/integrations/google/oauth.py`, `server/api/google.py`, `tests/integrations/test_google_oauth.py`
- Modify: `pyproject.toml`, `server/config.py` (`google: GoogleConfig | None = None`), `server/cli.py` (`ka google login|status`), `server/api/app.py`, `config.example.yaml` (keys with `set-me` values), local `config.yaml` (the owner's values)

**Interfaces:**
- Produces:
  - `GoogleConfig(client_file: Path, drive_folder_id: str, sheet_id: str)`. `client_file` has `~` expanded.
  - `GoogleAuth(cfg: GoogleConfig, token_path: Path)` with these methods:
    - `credentials() -> Credentials`: loads the token and refreshes it if expired. It raises `GoogleAuthError("reconnect Google")` when the token is missing or the refresh fails.
    - `email() -> str | None`: from the userinfo endpoint, cached in `app_state`.
    - `login_console() -> None`: `InstalledAppFlow.from_client_secrets_file(...).run_local_server(port=0)`.
    - `login_url(redirect: str) -> tuple[str, str]` and `finish(code: str, state: str, redirect: str) -> None`: the web flow. It uses the loopback redirect `http://127.0.0.1:<port>/api/google/callback`, with PKCE and `access_type=offline`.
  - Routes:
    - `GET /api/google/status`: `{connected, email, drive_sync, sheet}`.
    - `GET /api/google/login`
    - `GET /api/google/callback`: checks `state` against the stored value.
    - `POST /api/google/disconnect`

### Task 2: Drive and Sheets clients

**Files:**
- Create: `server/integrations/google/drive.py`, `server/integrations/google/sheets.py`, `tests/integrations/fakes.py`, `tests/integrations/test_google_clients.py`

**Interfaces:**
- Produces:
  - `DriveClient` Protocol, with `list_pdfs(folder_id) -> list[DriveFile]` (where `DriveFile(id, name, modified)`) and `download(file_id, dest: Path) -> Path`.
  - `SheetsClient` Protocol, with `replace_tab(sheet_id, tab: str, header: list[str], rows: list[list[str]]) -> None`. It creates the tab if it is missing, clears it, then writes with `valueInputOption="RAW"`, so amounts stay text.
  - `ApiDrive(creds)` and `ApiSheets(creds)` use `googleapiclient.discovery.build(..., cache_discovery=False)`.
    - The Drive query is `'<folder>' in parents and mimeType='application/pdf' and trashed=false`, with paging.
    - Downloads go to a temporary name, then are renamed into place.
  - `FakeDrive` and `FakeSheets` are for later tasks.
  - `ka google probe` lists the statements folder and reads the sheet title. It prints names only, no IDs.

### Task 3: Drive inbox to statement import card

**Files:**
- Create: `server/finance/drive_inbox.py`, `ui/src/features/pending/StatementCard.tsx`, `tests/finance/test_drive_inbox.py`
- Modify: `server/api/pending.py` (kind `statement`), `server/scheduler.py` (job `drive_sync` every 30 minutes when `flags.google` is on), `server/api/google.py` (`POST /api/google/sync`), `ui/src/features/pending/PendingPage.tsx`, `ui/src/lib/api.ts`

**Interfaces:**
- Consumes: T2 `DriveClient`; `prepare_import` and `commit_import`; plan 1 `queue_suggestions` (when `category_suggestions` is on).
- Produces:
  - `sync_drive(drive, cfg, db, now) -> SyncResult(new: int, skipped: list[str])`. It downloads unseen PDFs, runs `prepare_import` (with no LLM), and queues one `statement` card per file. The payload is `{file, statement_id, rows, money_in, money_out, checks, unknown_merchants, already_imported}`. A file that fails to parse is skipped with its reason and marked seen.
  - `approve_statement(item_id, cfg, db) -> str` re-runs `prepare_import` on the stored file, then, under `app.state.lock`, runs `commit_import`, then the suggestions, then the sheet copy (T4). `reject_statement(item_id, db)` rejects the card.
  - The card shows the file, period, rows, in and out amounts (monospace), the checks, and Import and Skip buttons.
